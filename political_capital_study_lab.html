Backup & portability
Everything is local: completion records, notes, reading checkpoints, cards, review history and intervals. No accounts, network calls, analytics, or external scripts.
Import merges records by ID and overwrites matching IDs. Export before importing. Browser data may be lost if site data is cleared or the file is opened from a different browser origin.
How to use the study engine
  1. Pick a week and one 30-minute session. Copy the complete prompt into ChatGPT.
  2. For close-reading sessions, supply the original reading text or excerpt where possible. Record the exact stopping point.
  3. Ask ChatGPT to respect the 30-minute structure; use its quizzes and answer orally or in writing.
  4. Mark complete only after actually studying; capture durable concepts as active-recall cards.
  5. Review due cards daily. Export backups regularly.
Reading fidelity and time budgeting
Each of four assigned reading clusters receives four 30-minute blocks. A long book chapter may require substantially more reading than four blocks permit. The prompt therefore requires a bounded passage and explicit checkpoint, not invented completion. Full reading of every assigned chapter may require extra time outside the 640-hour guided schedule.
Scheduling and algorithm
New cards begin due immediately. After a successful learning review, intervals expand using an ease factor; lapses return to learning. The algorithm is deliberately transparent and practical, not a claim to replicate proprietary SuperMemo algorithms. The review queue refreshes after grading.
File security
Do not put passwords or sensitive third-party data in study notes. The file does not transmit data, but browser extensions and other software with local access may be able to read browser data. Use a consistent browser and origin. For reliable persistence, serve this file from a stable localhost address; file:// IndexedDB behavior differs by browser.
